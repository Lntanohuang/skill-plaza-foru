# 004 · 历史会话点击后在在线运行主结果区展示

**状态**：已实现（2026-09-23）；历史点击/返回与新运行后的列表刷新已验收，新生成记录的再次点击复核被浏览器自动审批阻断。
**适用范围**：`web/src/pages/UsePage.vue`、`web/src/components/UseHistoryList.vue`、`web/src/styles/styles.css`。

## 动机

当前历史会话在列表项内展开原始输入/输出，表单模式放在右侧栏，对话模式还嵌套在原生 `<details>` 下拉中。长内容被限制在侧栏小区域内，用户需要在列表与结果之间来回阅读。在线运行页的主结果区才是用户理解一次运行的主要位置，因此历史列表应只承担选择，详情应显示在主结果区。

## 约定细节

- 数据接口不变：列表使用 `fetchRuns()`（`web/src/api/runsApi.ts:16-26`），详情使用 `fetchRunDetail(runId)`（`:34-47`）。
- `UseHistoryList`（`web/src/components/UseHistoryList.vue:6-47`）收窄为可滚动的历史任务选择器，向 `UsePage` emit 选中的 `RunListItem`；不再在组件内请求详情或展开全文。
- `UsePage`（`web/src/pages/UsePage.vue:382-489`）管理 `selectedHistoryId` 与按 runId 缓存的详情状态；详情从 trace 反向提取最后一条 user/assistant 文本 parts，沿用原有历史提取口径。
- 表单主结果区（`web/src/pages/UsePage.vue:704-764`）和对话模式历史结果区（`:851-881`）显示元信息、原始输入、Markdown 输出、加载/空态/降级态；提供“返回本次运行”，且不把历史内容回填当前表单或 `sessions`。
- 表单侧栏（`:822-833`）和对话侧历史栏（`:838-850`）统一为选择器，移除行内展开和下拉包裹。
- 请求按每个 `runId` token 防止竞态写入；相同 runId 的成功/降级结果缓存，避免重复读取 trace；运行中按钮禁用并保留轻量提示。
- 样式落在 `web/src/styles/styles.css:1893-1936`，历史输入块限制自身滚动高度，输出沿用 `.md-body` 排版。
- `live=false` 或 `trace=null` 继续按真实数据边界处理：不把 mock 冒充真实历史，只展示摘要和不可用提示。

## 成本与取舍

- 成本：详情状态从子组件提升到页面，增加少量状态与一个历史结果分支；换取表单/对话模式一致的阅读路径和恢复动作。
- 采用现有 `/api/runs/:runId` 而不是扩展列表接口，避免索引响应携带全文导致列表膨胀。
- 否决跳转 `/runs/:runId`：这是开发侧运行排查页，无法保持用户在在线运行工作台的上下文。
- 否决把历史内容写入当前 `sessions`：会污染当前会话上下文，并可能被误当作下一次提交内容。

## 后续扩展路线

- 若未来支持真正的多轮会话，可在选择器上按 `clientSessionId` 分组，但主结果区仍按选中 run 展示。
- 若 SSE `done` 事件回带 runId，可在完成后直接把新记录标为当前历史项，减少一次列表刷新后的手动定位。
- 若用户需要查看工具时间线、usage 或原始文件，继续从主结果区提供“查看完整运行记录”入口跳转开发侧详情页。
