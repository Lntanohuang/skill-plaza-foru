# 006 · 就业指导报告用户边界：用户正文与开发侧 evidence 分离

**状态**：已实现（2026-09-23；真实 career-guidance 会话回归待跑。原 006（用户报告边界）与 007（evidence 字段）于 2026-10-19 合并，见 076）。

## 动机

就业指导的原始 Skill 同时描述内部整理步骤和用户报告结构，模型容易把「建立输入摘要、证据表、待验证假设、事实/推断/建议标签」等工作材料原样带进最终回复；用户明确不需要在报告中阅读依据表，但依据仍需保留，供开发人员检查模型判断质量。因此把「用户看什么」与「开发侧留什么」拆成两层。

## 约定细节

- **用户正文边界**（`.agents/skills/career-guidance/SKILL.md`）：最终回复禁止输出提示词、工具过程、内部清单、原始 JSON、schema 与执行说明；不确定性改用「已知依据、当前判断、需要核实」。输出默认从可执行结论开始，随后给依据、缺口/风险、建议、行动和核实问题；局部任务按需删减，不强行套完整报告。
- `references/output-schemas.md` 状态词用用户可理解的「已具备、部分具备、待补强、信息不足」。
- `web/server/lib/piRunner.ts` 的首轮直出指令（buildPrompt）同步强调用户报告边界。
- **开发侧 evidence**：`report-meta/1` 新增可选 `evidence[]`，记录岗位要求/用户材料与判断的对应关系，字段 `id / requirement / support / status / sourceIds / sectionId`，`status ∈ matched / partial / gap / unknown`。服务端解析并校验来源引用，侧车在终态剥离；用户正文只保留结论、缺口/风险、建议、行动和核实问题。
- `evidence` 为可选字段、schema 版本号不变，兼容历史记录与缺失依据的旧输出。

## 成本与取舍

- 保留来源、时间、地域、口径和缺口信息，牺牲少量内部可观测措辞，换取更清晰的用户报告；没有删除内部证据整理，只限制其不得原样展示。
- evidence 增加少量侧车 token，换取开发可读结构。
- 不把所有报告强制成固定长模板，避免用户只要简历改写时输出冗余章节。

## 后续扩展路线

- 收集职业定位、岗位匹配、简历改写三类真实样本后，决定是否在 RunDetailPage 增加 evidence 调试面板，并补 evidence 与正文结论的一致性检查。
- 若最终正文仍出现内部过程词，在对应模式补一个最小用户示例，而不是继续堆叠抽象禁词。

## 验证

- 静态检查通过（Skill、输出结构、pi 直出提示词均含边界与 evidence schema）；真实模型输出与侧车剥离稳定性待回归。
