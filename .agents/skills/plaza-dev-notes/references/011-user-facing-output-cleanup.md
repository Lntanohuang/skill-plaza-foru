# 011 · 在线运行用户输出边界与图表展示

**状态**：已实现（2026-09-23；真实浏览器回归待完成）。
**适用范围**：`web/src/pages/UsePage.vue`、`web/src/components/ReportChart.vue`、`web/src/api/runsApi.ts`、`web/src/data/runsMock.ts`；开发侧运行详情与 trace 保留完整材料。

## 动机

在线运行页是给最终用户阅读结果的界面。当前结果区仍展示结构化 prompt/原始输入，执行过程折叠块在部分运行中实际承载的是 prompt 或模型旁白，且 Markdown 已渲染后又被普通文本再次输出。产业岗位数据（例如广州 Java 岗位学历结构）也需要从正文数字升级为可读图表。

## 约定细节

- 用户页删除“查看本次提交的结构化任务”、历史详情中的“原始输入”块，以及“执行过程”折叠块，已落在 `web/src/pages/UsePage.vue:747-763`、`:891-907`；对话模式中用户自己发送的消息仍保留为对话上下文。流式期间只保留轻量状态文案（思考中、调用工具、生成结果）。完整 prompt、工具时间线和原始 trace 只保留在开发侧记录/详情页。
- 用户页每次运行只渲染一份最终正文：`MarkdownView` 负责 Markdown；图表紧随正文；删除与 Markdown 同源的纯文本兜底，错误消息才允许以纯文本展示，已落在 `web/src/pages/UsePage.vue:731-764`、`:865-907`。历史结果沿用相同规则，不展示原始 Markdown 下载/全文块。
- 图表继续采用 `report-meta/2.charts` 结构化规格：Agent 输出 `type/title/data/sourceIds/unit` 等数据，服务端校验后通过 SSE `done.charts` 和运行详情返回，前端使用 `ReportChart` 渲染。学历占比、岗位排名优先 `bar` 或 `stackedBar`，比例使用 `%` 单位，并显示标题、地区/快照日期、关键发现和口径说明。
- 历史运行详情需同时带回已校验的 charts；`HistoryDetail.charts` 从详情 `item.report.meta.charts` 读取并在主结果区复用 `ReportChart`，已落在 `web/src/pages/UsePage.vue:394-470`。
- 只有通过来源完整性、数据点数量和类型校验的图表才展示；缺数据或校验失败时保留正文并标记“图表暂不可用”，不得由前端从任意自然语言百分比猜测数据。

## 成本与取舍

- 成本：在线页少一个“查看原始输入”的排查入口，历史详情类型和渲染分支需要扩展；开发侧 trace 与运行详情仍可追溯，因此不损失排障能力。
- 采用“结构化图表侧车 + 前端渲染”，不采用正则从 Markdown 抽取百分比，也不让模型输出 HTML/SVG；前者容易误识别口径，后者难校验且有注入和布局风险。
- 保留对话中的用户消息是为了维持多轮上下文；它不再作为“执行过程”或“原始输入”标签展示在结果卡片内。
