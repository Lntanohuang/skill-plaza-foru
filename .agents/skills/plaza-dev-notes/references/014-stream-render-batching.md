# 014 · 流式 Markdown 渲染批处理

**状态**：已实现（2026-09-24；构建验证通过，浏览器长报告体验待回归）。

## 动机

`/api/chat` 已按增量事件推送正文，但前端每个 token 都会让 `MarkdownView` 重新解析整篇文本。长报告在高频增量下产生重复 Markdown 解析，导致主线程抖动，用户看到输出停顿或成批刷新。

## 约定细节

- `web/src/components/MarkdownView.vue` 使用 50ms 短窗口合并 `text` 更新，再由 `computed` 执行一次 `renderMd`。
- 组件首次渲染仍立即使用初始文本；定时器在卸载时清理。
- SSE 协议、正文内容和最终 `done` 结果不变，批处理只影响浏览器渲染频率。

## 成本与取舍

- 代价是增量显示最多延迟约 50ms，换取长文本渲染次数显著下降。
- 未改后端节流，避免改变运行记录、SSE 时序和其他客户端行为。
- 被否决的方案：只增加 CSS 动画或滚动优化，无法降低 Markdown 解析成本。

## 后续扩展路线

- 浏览器端用长报告实测帧率、主线程耗时和首字延迟；如仍有卡顿，再考虑按段落增量渲染或虚拟化。
