# 027 · Pi-only 执行链与就业报告固定用户结构

**状态**：已实现（2026-09-29；真实报告回归待用户执行）。

## 动机

用户报告曾随模型自由发挥出现“任务范围与待确认信息”“已提供事实”“缺失信息”等内部整理型章节。与此同时，项目实际只使用 Pi，但运行入口仍保留 Zcode 双引擎、前端切换和 SQLite 补导链路，增加维护面并让报告/trace 行为不一致。

## 约定细节

- 执行引擎固定为 Pi：`web/server/index.ts` 只注册 `PiRunner`，`web/server/lib/runner.ts` 的 `EngineName` 只保留 `pi`；`/api/chat` 省略 engine 或显式传 `pi` 均可，其他值返回 400。
- 删除 Zcode 活跃接入：`zcodeRunner.ts`、`zcodeCli.ts`、SQLite trace 导出/补导脚本、Zcode 协议样例和旧 MVP 文档不再参与构建或启动。历史 `RunRecord.engine` 仍保留旧值兼容已落盘记录，不代表当前可选引擎。
- `web/server/lib/skills.ts` 的 `CAREER_GUIDANCE_USER_REPORT_CONTRACT` 与 `.agents/skills/career-guidance/SKILL.md` 共同约束正式 HTML 报告：h1 后固定六个 h2，依次为“结论与优先动作、岗位需求分析、岗位匹配、简历修改建议、行动清单、需要核实的问题”。当前任务/地区/岗位决定内容，不从示例默认值继承。
- 禁止把任务复述、输入摘要、已提供事实汇总、完整缺失信息、分析/思考过程、工具调用或模型说明做成正文章节、表格或清单；影响决策的限制就地简述，关键确认项集中在末章。
- Pi 首轮和后续轮次均注入该就业报告契约，避免常驻会话的旧结构影响新的正式报告；前端原有“请先复述任务边界”仍是独立的后续 P0 清理项，但运行时契约明确覆盖报告正文要求。

## 成本与取舍

- Pi-only 删除了 Zcode CLI 探测、app-server 桥、SQLite 导出和前端引擎切换，减少启动分支与维护代码；历史 trace 文件不删除，旧 engine 字段只作为兼容数据。
- 固定六章会减少模型在正式报告中的结构自由度，但换取用户可读性和不同运行之间的可比性；局部改写/简短答疑仍可不生成完整六章。
- 暂不加入服务端语义拒绝/自动重写；先用固定契约观察真实报告效果，若仍泄露内部章节，再在 `htmlReport.ts` 增加标题级质量门禁。
