## 约定细节

### 会话与查询
- 目标：广东省（深圳、广州城市切片）；技术领域＝人工智能与大模型应用、具身智能与机器人；窗口 1–3 年；高职；专业群＝软件技术、工业机器人技术。
- 沙箱 `AGENTS.md` **已同时含「联网检索工具」与「MySQL 只读查询工具」两节**，`web/.env` 的 `MYSQL_*` 已就绪——038 记录的凭据修复与工具节注入在本会话生效，034/035/037 的「跨 Skill 自行搬凭据 / Mock 未接入」问题在本会话不再复现。
- 共 10 批 20 条白名单查询（`--parallel`，每次 2 条，单批 46–69s）：`city-distribution`（province=广东省，大模型/机器人）2 条；深圳 `title-top`×2、`experience/salary/education`×12；广州 `title-top`×2、`salary-distribution`×1。全部 `ok:true`。
- **本次与 035/037 的关键差异**：显式传入 `roleTerms`。工具默认 `["后端","服务端","开发"]` 会把“机器人运维/调试/教师”等岗位挡在切片外；显式传入领域词后，同一 province 口径下城市分布改变——大模型切片深圳 51.2% / 广州 46.5%（037 默认口径为深圳 65.6% / 广州 21.8%），机器人切片深圳 64.3% / 广州 24.8%。**结论：`roleTerms` 必须随技术方向显式设定并在报告口径写明，否则城市集中度不可跨会话比较。**

## 成本与取舍

- **新增事实：`scripts/web-search.mjs`（cn.bing，038 已固定 `ensearch=1`）结果相关性随查询词剧烈波动。** 本次可用结果出现在「大模型 人才需求 报告 2026 高职」「人工智能 人才缺口 2026 报告 工信部」「人工智能训练师 …」等查询（gov.cn / qstheory.cn / 新华网可 `--fetch`）；但「机器人 人才 缺口」「IFR World Robotics」「广东省 机器人 政策」「具身智能 人才需求」等大量查询返回无关甚至垃圾结果（动漫/小说/导航站/Yandex 页），英文查询命中率更低。影响：tech-forecast 的“关键结论两个独立来源印证”在实际运行中难以稳定满足，机器人方向可追溯的需求趋势来源基本缺失，只能回退到“分析推断 + 库内实测”并在第七章写未评估。**建议：给 web-search 增加相关性过滤/重试，或在 Skill 检索纪律里补“结果无关时按未评估处理”的显式降级路径。**
- **否决：把默认 roleTerms 与显式 roleTerms 的分布混用比较**——两者分母不同，混用会得出错误的城市集中度结论；本次统一显式 roleTerms 并在图注写明。
- 接受限制：广州仅补 `title-top` 与 1 条 `salary-distribution`，广州机器人的学历/经验结构未查，报告未外推。
- PDF 抓取：`--fetch` 对 `application/pdf` 直接报「不支持的内容类型」，中国信通院《具身智能发展报告》PDF 无法取正文，只能作来源存在性引用或不引用。
