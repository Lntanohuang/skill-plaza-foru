# 任务 Issue 正文规范

`start-task.sh` 会自动生成以下信息。计划文件本身应保持短小，Issue 负责保存可追溯上下文。

```markdown
## 目标
一句话说明要交付的行为或结果。

## 范围
- 要改的模块、文件或接口

## 不在范围内
- 明确不做的事项，防止多 Agent 越界

## 验收条件
- [ ] 可观察的行为条件
- [ ] 必要的测试或检查命令
- [ ] 仍待验证的项目（如有）

## 计划
<计划文件内容>

## 开发上下文
- 仓库、分支、创建时提交
- 完成方式：成功 push 后由 Actions 关闭
```

Issue 标题使用 `开发计划：<短标题>`。不要把“已完成”写入创建时正文；完成状态由验证结果和 push 事件证明。
