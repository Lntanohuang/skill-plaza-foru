# 通用报告写作

本 Skill 只负责“如何把材料写成报告”，不负责具体业务数据、不负责图表绘制，也不负责文件保存。业务 Skill 负责业务口径、章节和输出需求；报告输出由 `report-output` Skill 处理。

## 工作原则

1. 先明确读者、任务目标、时间/地域范围和所需产物。
2. 将内容分为事实、推断和建议；事实必须有来源，推断必须说明依据和限制，建议必须说明行动对象和判断依据。
3. 每个重要数字保留单位、时间、地域、统计对象、分母和来源；无法确认时写“未评估/待核实”，不补造数据。
4. 报告从结论和行动开始，再给依据、限制和细节；不要把输入摘要、工具过程、内部推理或完整缺口清单冒充正文。
5. 结论应能回指到来源、指标或用户提供的材料；相互冲突的来源要说明采用口径和冲突范围。
6. 建议应可执行、可检查，写清优先级、产出物、完成标准和时间边界；不要把建议目标写成事实。
7. 只展示读者做决策所需的证据。内部证据表、查询日志和机器字段写入结构化产物，不直接塞进用户正文。

## 通用写作流程

1. 读取业务 Skill 的任务目标、受众、章节和输出要求。
2. 建立来源和指标清单，记录范围、时间、单位和限制。
3. 形成事实、推断、建议三类 claims，并为关键结论绑定依据。
4. 按业务章节组织正文：先结论，再证据，再限制，最后行动。
5. 按业务 Skill 要求调用图表 Skill；图表只展示已验证数据，不用图表掩盖证据缺口。
6. 按 `report-output` Skill 写入用户产物和 `report.artifact.json`，完成最小结构检查。

## 结构化证据

需要生成机器可读报告产物时，使用 [统一证据模型](references/evidence-model.md)。该模型是最小公共字段，不要求所有业务使用相同章节或相同扩展字段。

## 禁止事项

- 不编造来源、数字、用户经历、公司信息、政策或录用结果。
- 不把数据库记录数直接解释成整个市场规模或实际就业人数。
- 不把模型推断写成已验证事实。
- 不把报告生成过程、提示词、工具调用或 Skill 名称写入用户正文。
