# 新岗位·新技术报告生成

系统需实现新岗位与新技术预判相关能力：
支持开展新兴技术成熟度分析，通过雷达图可视化呈现技术成熟度、产业影响力、人才缺口等多维度指标；
支持技能演进路径分析，借助桑基图直观展示传统技能向新兴技能的演进关联关系；
支持新兴岗位预测，输出岗位名称、预计薪资、需求趋势、所需技能、匹配专业等信息；
支持生成培训方向建议，涵盖技术方向、建议课程、实训重点、匹配专业、紧迫程度等内容；
同时支持新兴技能预测，展示技能名称、关联岗位、技术领域、增长趋势等相关信息。

## 工作流程

### 一、输入

1. **库内实测**

获取方式：优先读取 Skill 内置快照 `references/data/`（覆盖索引见 `references/data/README.md`，含快照日期与切片口径），命中当前地区×领域×关键词组合时直接引用快照表格（引用时注明快照日期）；未命中、或快照超过 90 天、或需要快照没有的维度时，才调用会话岗位白名单库实时查询（使用标准关键词表，分新兴切片、传统对照切片执行查询；涉及地区数据使用指定 MySQL 只读工具，传入 queryId 与 JSON 参数，禁止手写原始 SQL，最多并发 2 条查询），并在报告中标注"快照未覆盖，实时查询"。

注意事项：仅采用比例、分布、排序结果，不能把抓取条数当作市场总量；岗位抓取批次时间不等于真实发布时间，不能用库内计数生成市场趋势曲线；查询失败标记"未评估"并写明原因；保留筛选口径、快照日期。

2. **公开来源**

获取方式：调用指定检索脚本，每个技术领域至少执行一次检索，中英文关键词组合查询，对目标网页执行正文抓取。

注意事项：优先选取近 24 个月、有明确机构署名的报告、政策文件；论坛、自媒体仅作旁证；关键结论尽量两个独立来源交叉印证，单一来源需要明确标注；引用记录标题、网站、发布日期，简短转述，禁止大段复制原文；检索无结果标记"公开来源未检索"，回退其他材料，禁止编造内容。

3. **内置文档**

获取方式：读取 Skill 自带快照文档（`references/` 目录：技术清单 technology-snapshots.md、演进对照 skill-evolution-map.md、专业对照 major-mapping.md）。

注意事项：记录文档快照日期、编辑判断属性；遇到文档未覆盖的技术、地区，标记"内置文档未覆盖"，可做分析推断且必须写明依据，严禁编造数据。

4. **分析推断**

获取方式：基于库内实测、公开来源、内置文档已有材料做外推研判。

注意事项：每条推断需要写明推导依据以及验证办法，不得和实测类数据混淆；仅作为补充手段，不作为原始数据源。

### 二、数据整理切入维度

| 数据分类 | 核心加工角度 | 支撑报告模块 |
| --- | --- | --- |
| 新兴技术数据 | 技术基础属性；成熟度、产业影响力、人才缺口、生态完善度指标；评分口径与证据等级 | 新兴技术成熟度分析 |
| 技能演进数据 | 技能标签（传统/新兴）；新旧技能关联映射；演进流量权重；关系溯源标记 | 技能演进路径分析 |
| 新兴岗位数据 | 标准化岗位库；岗位-技能关联；招聘时序需求；薪资区间+统计口径；岗位-专业匹配；可信度标记 | 新兴岗位预测分析 |
| 新兴技能数据 | 标准化技能实体库；技能-岗位关联；技术领域归属；技能时序增长趋势；证据等级标记 | 新兴技能预测分析 |
| 人才培养派生数据 | 课程-技能映射；专业-技能映射；基于技术、岗位、缺口综合计算紧迫程度、留存判定依据 | 人才培养方向研判 |
| 元数据与质量管控 | 数据源、快照时间；可信度分级规则；缺失/未评估项记录；待核验问题清单 | 数据说明与评估局限 |

### 三、参考报告结构

1. **分析摘要**：整合本次研判形成的综合研判结论，归纳技术发展态势、岗位与技能演变特征，输出综合研判观点与衍生启示。
2. **新兴技术成熟度分析**：通过雷达图呈现各项技术在技术成熟度、产业影响力、人才缺口、生态完善度多维度评分；配套维度评分表，明确标注评分计算口径、推断证据等级。
3. **技能演进路径分析**：采用桑基图可视化呈现传统技能向新兴技能的演进转化关系；图注明确图表流量语义、证据数据来源，同步输出技能演进主要方向的解析内容。
4. **新兴岗位预测分析**：以表格形式展示岗位名称、预计薪资（附带薪资统计口径）、需求趋势（标注证据等级）、岗位所需技能、可匹配专业；岗位名称、薪资区间优先依托岗位数据库做校验佐证。
5. **新兴技能预测分析**：以表格整理技能名称、关联岗位、所属技术领域、技能增长趋势，并标注对应证据等级。
6. **人才培养方向研判**：输出技术方向、建议课程设置、实训核心重点、适配专业、需求紧迫程度；紧迫程度结论需要结合前文技术、岗位、技能分析写明判定依据。
7. **数据说明与评估局限**：汇总报告所使用的数据来源、快照时间，说明推断分级规则；列明未评估项及成因；最多列出 3 项有待进一步核验的关键问题。**章节末尾以编号列表输出"参考文献"**：列出本报告全部引用来源（含库内快照与公开来源），条目格式 `[n] 标题／网站（或数据源）／发布（快照）日期／链接`，与正文 `[n]` 标记一一对应。

### 四、产物如何呈现

1. 完整报告固定输出至 `workspace/report.html`，写入完成后由服务端校验并提供报告链接。
2. `report.html` 为可独立打开的完整 HTML 文档，必须包含 `<!doctype html>`、`<html>`、`<head>`、`<body>` 基础标签；正文采用 HTML 标题、段落、列表、表格、figure 标签组织内容，事实、判断、建议均写在文档正文内。
3. 报告内量化数据遵循图表规则使用内联 SVG，保留 `data-chart-skill` 属性。
4. **引用编号标记**：正文（含表格单元格与图表 figcaption）中每处证据引用以上标形式标记：`<sup>[1]</sup>`（右上角、字号小于正文），编号按首次出现顺序分配；同一来源多处引用复用同一编号。第七章"参考文献"编号列表与正文标记严格一一对应，缺列表或对不上视为报告未完成。
5. **标题排版**：h1 报告标题不得出现括号（全角／半角均不可），补充说明（如"含数字化转型"）写入副标题行或正文首段；各章节标题同样避免括号。
6. 报告写入后仅执行最小化存在性、结构校验，不读取文档完整内容。

### 五、注意事项

1. 报告仅输出可供决策使用的结论、约束条件、落地行动，不得包含分析过程、提示词、工具调用记录、内部清单、模型/技能说明、过程类描述话术。
2. **充分支撑呈现原则**：报告只呈现有充分证据支撑的内容与结论。证据不足的条目、维度或切片直接不进入正文——用沉默代替自曝，不出现"样本不足""仅 X 条""几乎无样本""不足以支撑"等削弱专业性的表述；不得为填补空缺编造数据。证据分级标注保留（分级是专业性的一部分），但用中性措辞；数据来源、统计口径与适用边界集中在第七章以专业口径说明，不在正文中反复罗列数据覆盖类元信息。影响决策方向的关键限制（如政策不确定性）仍须专业表述呈现。
3. 报告与回复中禁止输出原始 JSON、schema、机器校验类字段；不要把 HTML、SVG、代码块、Markdown、JSON、文件内容复制粘贴到最终回复。

## HTML 图表与绘图 Skill

每一张图表都必须使用共享 chart-visualization Skill 的对应参考文件，按其结构生成一个 HTML figure，并在根元素上写明 `data-chart-skill`。参考路径是项目工作区的 `.agents/skills/chart-visualization/references/`：

- 雷达图（技术成熟度多维评分）：读取 `radar-chart.md`
- 桑基图（技能演进路径）：读取 `sankey-chart.md`
- 柱状图（岗位量/薪资区间对比）：读取 `bar-chart.md`
- 堆叠柱状图（学历/经验构成）：读取 `stacked-bar-chart.md`
- 折线图：仅当公开来源提供了带明确时间口径的真实序列时使用（引用来源），读取 `line-chart.md`；岗位库数据不得绘制任何时间趋势图

每个 figure 必须包含标题、可访问文本、来源/快照口径和内联 SVG；禁止使用外部图表库、JavaScript、Base64 图片或仅用表格替代图表。雷达图维度评分与桑基图流量都必须标注证据等级；数据不足时保留"未评估"状态块，不绘制无数据的 SVG。单张图数据点与节点数按绘图 Skill 上限执行。
