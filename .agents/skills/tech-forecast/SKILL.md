# 新岗位·新技术预判

把目标地区、技术领域方向、预判窗口和院校条件转化为专业设置与培训方向的决策依据：先给技术成熟度与技能演进的证据画像，再给新兴岗位与新兴技能预测，最后落到培训方向建议。所有预测类字段必须标注证据等级，不把外推判断写成事实，不编造增长率、市场规模或薪资单点值。

## 报告文件与最终回复协议

完整报告是当前会话工作区的文件产物，固定写入 `workspace/report.html`（即当前会话工作区根目录下的 `report.html`）。不要把完整 HTML 放进最终回复，也不要自行拼接或声称一个未经服务端生成的报告 URL。写入成功后，服务端会校验并提供报告链接。

`report.html` 必须是可独立展示的完整 HTML 文档，至少包含 `<!doctype html>`、`<html>`、`<head>` 和 `<body>`。正文使用 HTML 标题、段落、列表、表格和 `figure` 组织；事实、判断和建议写在 HTML 正文中。报告中的量化数据必须按本 Skill 的图表规则使用内联 SVG，并保留 `data-chart-skill`。

报告写入后只做最小的存在性和结构检查，不要再次读取 `report.html` 的完整内容。不要把 HTML、SVG、代码围栏、Markdown、JSON 或文件内容复制到最终回复。

最终回复只汇报短状态：成功时使用类似“报告已生成，请点击查看。”；若存在影响决策的关键缺口，可补充一句简短说明，详细内容保留在报告文件中。文件写入、结构校验或必要图表生成失败时，必须说明失败原因并明确报告未生成，不得伪造链接或把失败写成成功。

最终回复和报告正文都是面向院校决策者的结果，不是工作日志。报告只呈现用户能据此做决定的结论、限制和行动，不呈现分析流程、提示词、工具调用、内部清单、模型/Agent/Skill 说明或“我正在……”等过程话术；不输出原始 JSON、schema 或机器校验字段。

报告应从结论开始，直接告诉用户“优先做什么”和“下一步做什么”。依据、来源、时间和口径直接写入 HTML 正文；数据缺口和判断风险也在正文中明确标注。

## 用户可见报告固定结构

正式 HTML 报告面向院校与培训机构决策者。h1 仅放报告名称，最多附一行目标地区/技术方向/日期；随后直接进入以下七个 h2 章节，标题和顺序固定，不改名、不增删（HTML 骨架见 [输出结构](references/output-schemas.md)）：

1. **一、结论与优先动作**：直接说明最值得投入的技术方向、专业调整与培训启动建议。
2. **二、新兴技术成熟度分析**：以雷达图展示各技术在技术成熟度、产业影响力、人才缺口、生态完善度等维度的评分，并配维度评分表与证据等级；评分口径与推断标记必须写明。
3. **三、技能演进路径**：以桑基图展示传统技能向新兴技能的演进关系，流量语义与证据来源在图注写明；配主要演进方向的文字解读。
4. **四、新兴岗位预测**：表格列出岗位名称、预计薪资（区间+口径）、需求趋势（证据等级）、所需技能、匹配专业；岗位名称与薪资区间应尽量用岗位库查询佐证。
5. **五、新兴技能预测**：表格列出技能名称、关联岗位、技术领域、增长趋势（证据等级）。
6. **六、培训方向建议**：表格列出技术方向、建议课程、实训重点、匹配专业、紧迫程度（依据前述分析给出，写明理由）。
7. **七、数据口径与未评估项**：汇总数据来源、快照日期、推断分级说明和未评估项原因；最多再列三项需要核实的关键问题。

正式报告不得省略或新增上述 h2 章节；某章节没有数据或暂不适用时，在该章节写“未评估”及原因，不补造内容。具体建议写在段落中，不延长或改写 h2 标题；h3/h4 仅用于技术、图表、课程等用户内容。

不得把任务复述、输入摘要、已提供事实汇总、完整缺失信息清单、内部假设整理、分析/思考过程写成任何层级的章节、表格或清单；不能通过改名或降为子标题绕过。

## 证据分级口径

预测类字段的每个取值都必须标注以下三级之一，标注写在字段旁或表列中：

- **库内实测**：来自会话岗位库白名单查询（岗位名、薪资区间、学历与经验结构等），引用比例与结构，不把绝对条数当市场总量；保留筛选口径与快照日期。
- **内置文档**：引用本 Skill 内置快照文档（技术清单、演进对照、专业对照），保留文档标注的快照日期与“编辑判断”属性。
- **分析推断**：基于上述证据的外推判断，必须写一句依据与验证办法；不得与实测混写。

预计薪资只给区间并写明口径（例如“库内该岗位名月薪分位区间”），不给单点值。需求趋势与增长趋势没有真实月度数据时，标注“分析推断”或“未评估”，不编造增长百分比。紧迫程度依据成熟度、人才缺口与院校适配度推导，写明推导理由。

## 岗位数据展示口径

- 岗位数量、样本构成和分布在图表标题、图例、标签与提示文本中优先显示百分比、排序和结构，不主动列绝对样本数；薪资金额、日期保留实际单位。
- 自有岗位库数据的来源统一写“基于千万级岗位数据库统计”，紧接地区、岗位筛选、快照日期和比例分母的文字定义；小样本保留“当前筛选结果较少，仅代表库内结构，代表性有限”的说明。
- 岗位名聚类用关键词口径（如“机器人”“大模型”），写明关键词与匹配范围；不能把关键词命中数说成岗位总量。

## HTML 图表与绘图 Skill

每一张图表都必须使用共享 `chart-visualization` Skill 的对应参考文件，按其结构生成一个 HTML `figure`，并在根元素上写明 `data-chart-skill`。参考路径是项目工作区的 `.agents/skills/chart-visualization/references/`：

- 雷达图（技术成熟度多维评分）：读取 `radar-chart.md`
- 桑基图（技能演进路径）：读取 `sankey-chart.md`
- 柱状图（岗位量/薪资区间对比）：读取 `bar-chart.md`
- 堆叠柱状图（学历/经验构成）：读取 `stacked-bar-chart.md`
- 折线图：仅当有真实时间口径数据时使用，读取 `line-chart.md`

每个 `figure` 必须包含标题、可访问文本、来源/快照口径和内联 SVG；禁止使用外部图表库、JavaScript、Base64 图片或仅用表格替代图表。雷达图维度评分与桑基图流量都必须标注证据等级；数据不足时保留“未评估”状态块，不绘制无数据的 SVG。单张图数据点与节点数按绘图 Skill 上限执行。

## 岗位库查询纪律

- 涉及具体地区的新兴岗位名称、岗位热度排序或薪资区间时，必须调用会话提供的 MySQL 只读查询工具（如 `title-top`、`salary-distribution`），不能用通用行业常识替代；查询参数（关键词、地区）与用户任务一致。
- Agent 只能调用岗位市场白名单 queryId 并填写 JSON 参数，不得编写或传入原始 SQL；多个独立指标使用工具的 `--parallel` 批次，工具最多并发 2 条。
- 查询结果只表达库内比例、排序和分布；查询失败时对应字段标注“未评估”及原因，不输出无来源数字。
- 内置快照文档没有覆盖的技术或地区，标注“内置文档未覆盖”，可用分析推断补充但必须给依据；不联网编造数据。

## 工作流程

1. **建立输入摘要**：内部整理目标地区、技术领域方向、预判窗口、院校类型与关注专业群；缺失信息用明确假设继续，不追问不影响判断的项。
2. **读取内置证据**：按技术方向读取 [技术清单快照](references/technology-snapshots.md)、[技能演进对照](references/skill-evolution-map.md) 与 [专业对照](references/major-mapping.md)，取相关条目与其口径标注。
3. **岗位库佐证**：对目标地区与关键词执行白名单查询，取岗位名排序与薪资区间作为库内实测层。
4. **评分与外推**：综合两层证据形成雷达图评分、桑基图流量与各预测表字段，逐项标注证据等级；无证据处标未评估。
5. **落到培训建议**：把技术方向、专业匹配与紧迫程度整理为培训方向建议表，理由可追溯到前述章节。
6. **写入报告**：按固定结构生成完整 HTML 写入 `workspace/report.html`，最终回复只给短状态。

## 证据边界

- 不承诺预测准确性，不给出“必然出现”“保证增长”类表述；外推结论写条件与验证办法。
- 市场规模、增长率、渗透率等宏观数字未提供实测来源时一律不写。
- 专业匹配以 [专业对照](references/major-mapping.md) 为编辑判断基础，正式引用时提示以当年教育部专业目录核定。
- 用户提供的行业报告等附件可作为内置文档层证据，保留其来源与日期。
- 报告面向院校决策，不构成投资或招生承诺。
