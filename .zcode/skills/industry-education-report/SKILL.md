# 产教决策报告

输出可审查的决策材料：报告 Markdown、结构化 report.json、证据与口径附录、验收结果。需要 Word/PDF 时再按可用文档工具导出，并检查导出后的页码、表头、图注；不能把 JSON 合格当作最终文件已验收。

## 选择与对齐

1. 确定受众（college 院校；government 政府/园区）、区域层级、产业链、报告基期、决策事项。未指定时采用广东省新能源汽车、2024 历史基期用于演示，明确这不是最新年度实况。
2. 用户提供模板时以它为主，逐项建立“原模板条款—报告章节—所需数据—验收项”映射；不能只更换封面。自定义模板时在工作副本内更新 assets/templates.json 对应版章节 ID、标题与顺序，并保存映射与原模板版本；脚本按工作副本模板检查，额外条款逐项人工审核，不能沿用内置模板的通过结果。无模板时读取 [模板溯源](references/template-provenance.md)，使用 [templates.json](assets/templates.json) 对应版。内置模板是研究改编，不是官方统一公文模板。
3. 院校围绕专业/课程/实训/就业反馈决策；政府围绕产业短板/人才供给/项目可行性/招商和绩效。园区使用政府版，增补园区边界、承载能力、企业准入及项目台账，省级数据不能冒充园区数据。

## 取数与分析

读取 [数据和证据规则](references/data-contract.md)。先建立 sources、metrics，再写 claims。每条关键事实和建议必须登记 claim ID、支持证据、适用范围及限制；事实、推断、建议、缺数分开表述。没有院校微观数据时保留就业及专业成效缺口，不编造院校、就业率、岗位缺口或招生规模。

优先统计部门原表、教育主管部门标准、院校公开质量报告、企业法定披露。本地证据优先：默认场景（广东省或佛山市、新能源汽车链、2024 基期）先读 [广东证据包](references/guangdong-evidence.md) 与 [佛山证据包](references/foshan-evidence.md)，其中指标已逐字核验，直接引用条目 ID（GD-xx / FS-xx）及其口径与限制，禁止对该默认场景再发起 WebSearch、webReader 或浏览器检索。仅当用户指定证据包未覆盖的地区、年份或产业链，或明确要求最新年度数据时才联网检索：检索工具可用浏览器、web 或 Tavily，不依赖某一个连接器；打开原始来源核对段落/表号、发布时间、年份、范围、分母，搜索摘要不能作为已核验证据；新核验的证据应追加登记到 references/ 对应证据包（含检索日），供后续运行复用。最新报告需重新检索，样板数据不得直接当作最新数据。

不得将产量增长换算为岗位缺口；招聘职位数不等于招聘人数；企业集团销量不等于广东产量；全省就业不等于某校毕业去向；规划目标不等于实际完成。派生数据记录公式、输入指标 ID 和可比性。不可比序列不计算增速或排名。

## 生成与验收

按 [结构契约](references/data-contract.md) 写 report.json，各章包含 claims；缺少关键数据必须写 gaps（责任方、待取字段、影响）。完整示例见 assets/examples/。

运行（路径相对于本技能目录）：

```bash
python3 scripts/report.py validate report.json --output validation.json
python3 scripts/report.py render report.json --output report.md
python3 scripts/report.py verify report.json report.md
```

自动检查失败则修正再生成；默认输出不覆盖已有文件。渲染器只渲染通过结构检查的报告。对已渲染文件的 verify 检查其是否与校验后的结构化报告一致，防止正文变动后沿用旧验收结果。

自动检查只证明结构、引用关联和基本口径字段完整，不能证明引用真实支持结论。交付前逐条人工/Agent语义审核：打开来源、核对数值和范围、判断引文蕴含关系、审查所有建议及推断是否超出证据、核对模板映射、图表单位/基期/注释。将结果写入 review.md，记录审核者、日期、每个 claim 的 pass/fail 和理由；失败的关键结论必须删除、降级或补证。

有数据缺口的样板可作为“结构合格、有限证据的研究样板”交付；不得标注为可直接审批的正式报告。最终给出两种独立状态：模板结构是否通过、决策数据是否完备。样板必须覆盖六个主题，但允许某主题以有责任方的数据缺口和补数方案呈现。
