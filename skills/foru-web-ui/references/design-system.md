# 页面设计体系

来源为 [FORU 首页](https://foru-ai.com/)，采集日期 2026-09-14。下表为浏览器 computed style / 已加载 CSS 的实测值；“建议”另行标注。

组合规则：导航和卡片主体保持白，浅蓝负责外围背景与默认入口，饱和蓝集中在选中项、行动和企业头部。Hero中的蓝紫青来自插画的透明层与局部高光，不能把这些插画色扩成正文底色。伙伴区域可使用较强玻璃底和阴影，其他正文、导航、产品入口以清晰白色表面为主。

实现状态、企业头部、伙伴材质与替代插画时读 [color-recipes.md](color-recipes.md)。其中分开列出源样式配方和重建近似值，避免将一组颜色平铺到所有组件。

| 项目 | 实测参考 |

| Hero 入口 | 高 42px，圆角 21px，左右 padding 20px，间距 16px |
| 实际首页区块标题 | 34px / 50px，letter-spacing 1px，下距 22px；原字体别名 HP-Medium、computed weight 400 |
| 区块副标题 | 16px / 23px |
| 常规区块留白 | 上下各 60px |
| 普通卡片标题 | 18px / 26px |
| 卡片正文 | 14px / 20–24px |
| 产品卡片标题 | 20px / 28px |
| 功能标题 / 正文 | 20px / 30px；16px / 24px |
| 标签 | 12px，行高 24px，圆角 4px，左右 padding 10px |

中文字体声明含 `PingFangSC-Regular`、`PingFangSC-Medium`、`HP-Regular`、`HP-Medium`；数字统计规则使用 `DM Sans`。迁移建议使用系统中文字体或项目已有的合适字体，不复制大量原站分片字体。HP-Medium 的字面名称与浏览器 weight 400不能直接换算成系统字体：系统替代的区块标题建议先用500并视觉核对，避免加成700而让标题比原站更黑更厚。Hero H1 的900是单独规则。注意通用 `.home-part-title .title` 有 40px 声明，而实际首页 `.column-header .column-title` 是 34px；以页面实际使用的类为准。

## 首页信息架构

| 顺序 | 模块 | 可迁移的设计逻辑 |
| --- | --- | --- |
| 1 | 固定导航 | 品牌、产品菜单、方案菜单、直达入口、登录行动 |
| 2 | Hero | 技术能力 → 服务对象与结果 → 两个业务入口 |
| 3 | 产品生态 | 先选角色，再选择可用产品 |
| 4 | AI+X 解决方案 | 一个展开项 + 三个窄项，以插画展示行业 |
| 5 | 能力转化平台 | 一张流程关系图，解释供需与能力转化 |
| 6 | AI 功能与统计 | 左侧四个功能、右侧联动界面图；随后是八类指标 |
| 7 | 产业链 | 横向收拢图片卡片，当前项扩大 |
| 8–12 | 园区、企业、岗位、院校、人才 | 按实体类型组织不同卡片结构 |
| 13 | 生态伙伴 | 合作 Logo 矩阵与较大的蓝色玻璃面板 |
| 14 | 新闻动态 | 桌面一页三张卡片，分页圆点；异步失败时可能缺失 |
| 15 | 选择理由 | 三列：方案、服务能力、资质 |
| 16 | 页脚 | 深色底、快速入口、协议、联系与关注信息 |
| 独立 | 右侧浮动服务 | 四项服务胶囊 + 独立 AI 助手圆按钮 |

结构服务于业务，不要求所有项目采用 16 个模块。保留“角色入口 → 场景 → 能力证明 → 资源 → 信任”的递进关系即可。

## 组件规格与状态

**角色 Tab 与产品入口。** Tab 实测外宽 208px、高 52px、上圆角 16px，间距 16px；选中蓝底白字。面板左右 padding 40px、上下 60px，圆角 `0 22px 22px`。个人初始四项均分，卡片 256 × 160px，gap 32px。原站 hover 用 `155.11deg, #9AC2FD 14.264%, #165DFF 93.013%`，标题变白，56px 图标收为36px并进入白色圆角底。卡片数量随角色变化，不能硬编码四列为全部状态。

**解决方案。** 原 CSS 普通项 242 × 352px，展开项 420 × 352px，圆角16px，最终布局受 Flex 收缩影响。展开项增加白色标题、16px说明、白色胶囊详情。采用可收缩比例或 Grid，在1200px里留出真实间距，不直接相加固定外宽。详见前端参考。

**AI 功能。** 四项纵向排列于细描边时间线。选中项有白色面板、12px圆角、蓝色标题、标签，以及左侧4px蓝色进度条；右侧图示同步变化。图示承担证明能力的作用，应使用目标产品的截图或原生绘制的界面。

**产业链。** 普通卡片宽106px，选中245px，高234px，gap13px，12px圆角，宽度 transition 1s。选中项底部渐变遮罩露出标题。重建时可调整比例以匹配新的数据数量；移动端改为横向可滚动列表或普通卡片。

**园区卡片。** 桌面4列，图高179px，文字区 padding `16px 18px 26px`，蓝色区域标签覆盖图与文字交界。标题18px，地址14px，11px圆角。hover 上移7px。

**企业卡片。** 桌面3列，gap约24px，宽约384px，蓝渐变头部含56px Logo、白色企业名和行业元信息。白色内容区包含两个岗位及右对齐地区。

**岗位卡片。** 桌面3列，同排等高。上方岗位名与右侧蓝色薪资；中部浅蓝标签；底部浅色公司条。长标题截断，标签可换行，不用所有标签填满卡片。

**院校与人才。** 院校卡片用70px圆 Logo + 名称/类型；人才卡片分头像与基础信息、彩色技能标签、摘要、时间线三层。迁移时使用经确认的业务内容。

**伙伴、新闻、理由。** 伙伴标题在玻璃板上方的白色区域；板为24px圆角，矩阵白底Logo小板。本轮 [完整伙伴截图](screenshots/desktop-partners.jpg) 可见桌面5列3行，以及玻璃后方由白色波形过渡到饱和蓝的局部背景。列数随目标伙伴数量调整，不填空板凑列；不能只在白底上复制玻璃CSS，也不将伙伴标题区域全涂蓝。新闻用174px高封面、18px标题、14px摘要和日期，18px圆角、hover上移8px；理由三列卡片共用标题、64px图标与四条能力说明。

## 文案与插画迁移

文案用简短的行业陈述表达“谁、做什么、获得什么”。Hero可用“AI能力 / 连接业务生态”两行，副标题列出最多三个可理解的结果；入口使用动作或产品名。区块名保持短而明确。示例文字应说明是示例，不伪造平台规模、客户或资质。

原站插画以白色基座、半透明蓝青立体结构、蓝紫AI标识为主，行业区块加入汽车、机械臂、商业建筑。原Hero的背景图延展到整个首屏：左侧文字背后很浅、下缘淡出为白，右侧蓝紫结构、青色透光与蓝色边缘更集中。替代素材保持这类亮度分布、材质和透视；均匀铺满青色的矩形背景会明显偏离参考。

产品入口的图标也不是单色扁平按钮：原截图可见蓝青课程帽、蓝紫测评、嫩绿工作入口、蓝色配绿色项目入口。允许少量绿、紫点缀，但它们留在图标和内容分类中，Tab、链接与行动仍用品牌蓝。CSS/SVG可重建层叠形状、侧面、局部高光来保持图标语气；要求近似立体插画时使用自有或生成素材。位图中的蓝紫青不能从截图采样后宣称为官方token。装饰性素材不包含必读文字。
